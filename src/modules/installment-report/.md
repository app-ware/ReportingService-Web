# Installment Report Export: Design

> Mirrors `src/modules/receipt-report` and `src/modules/invoice-report` (see their `.md`): same
> split, same conventions. Design approved 2026-11-03.
>
> **Status (2026-11-10):** this service's side is implemented as designed: `POST /reports/installment`,
> `installmentReportSchema`, `installment-report.hbs`, en/fr/ar labels, and the shared
> `ReportLayout.textFooter` option (§3). The NurseryServices-Web side (§7) is next.

## 1. Overview

Renders the **single-installment slip** PDF for one installment of a tuition invoice. Legacy:
`ExportInvoiceInstallmentsData()` (C# WCF), SPs `getInvoiceInstallments` / `getInvoiceInfo`,
Crystal Reports `InstallmentReportSmall.rpt` / `InstallmentReportSmallCustomized.rpt`. It uses the
**Invoice** printable-report settings (`PrintableReport_Types.printable_report_type_id = 1`). Legacy
calls `GetPrintableReportSetting(CenterID, PrintableReports.Invoice)`, so there is no new report type
row. The division of labor is the same as the other reports: **NurseryServices-Web does all data
aggregation, amount and date formatting, amount-in-words and image resolution**. This service stays
"dumb": JSON in, PDF out.

**Ground truth used for this doc:**
- The legacy C# method (supplied directly).
- Both SP bodies, read from the staging replica (`OBJECT_DEFINITION`). They are summarized in §2.
- Three real legacy PDFs, all the single-installment layout, all A5 landscape (595×419 pt), all
  Demo Center (10000) with Invoice `use_images = true`:
  - `Mazen cxbcxb Installments.pdf`: invoice 51826, installment 1/10, **Pending**
  - `Farah full test Installments.pdf`: invoice 51915, installment 1/4, **Paid**
  - `child 2 class tuition 1 by osama Installments.pdf`: invoice 51925, installment 1/12, **Pending**
    (exported from a system whose parent and child names differ from the staging replica. Layout is
    unaffected.)
- The legacy Invoice sample (`[Demo] mostafa gg55 test bulk class student Invoice.pdf`, same center),
  which has the **same bottom image** as the slips. The modern invoice report already renders that
  image as the Invoice **footer banner** (`report-footer-banner` partial), so the slip does the same.

### 1a. Scope: the slip only, not legacy's full schedule

Legacy has a second layout: `InstallmentsReport.rpt` / `InstallmentsReportCustomized.rpt`, printed
when `InstallmentID` is omitted, with every installment of the invoice. **No legacy UI path was found
that requests it.** All three samples came from the per-installment print. It is **deliberately not
ported** here. If it is ever wanted, the contract in §4 extends cheaply: `installment` becomes an
array, and the page format comes from the payload.

### 1b. Related, separate: the invoice report's half-built `installmentSchedule`

NurseryServices-Web commit `88e221b` (Rawan, 2026-10-15, on `develop`) added
`GET /tuition/invoices/export/:invoiceId/ticket?includeInstallments=true`. That sends an optional
`invoice.installmentSchedule = { rows: [{ number, dueDate, amount, status }], total }` inside the
**invoice** payload and names the file `"… Installments.pdf"`. This service's `invoiceReportSchema`
does not declare that field, and the validator **strips unknown fields**. `invoice-report.hbs` has no
table for it either. So that path currently downloads a plain invoice under an "Installments" name.
**That is a separate feature (an invoice-with-schedule layout) and is not part of this work.** It is
noted here so it is not mistaken for this report. The owner is being told separately. Nothing in this
design depends on it or changes it.

## 2. Data flow

### 2a. What legacy reads (from the SP bodies)

`getInvoiceInstallments(@invoice_id, @installment_id)`:
- `Fees_Installments` for the invoice, `installment_status <> -1`, numbered
  `ROW_NUMBER() OVER (ORDER BY fee_installment_id)`. `installments_count` is the count of the same
  set. That is where the slip's **"1 / 10"** comes from: the number is the installment's position
  **among the non-deleted installments, ordered by id**, not by due date.
- Joins `Child_Invoice` → `Care_Center` → `Currency` (`currency_name`), plus `LEFT JOIN Child_Payments`
  (`installment_id`) and `Payment_Type`.
- Formats in SQL: `due_date`/`payment_date` → `dd/MM/yyyy` (style 103), amounts →
  `Cacheamountformat`, words → `Tafkitgenerator(installment_amount, currency_name)`.
- Filters to `@installment_id` **after** numbering, so a single installment keeps its real position.

`getInvoiceInfo(@invoice_id)`:
- `Child_Invoice` → `Child` → `Class_Child` → `Class` → `Parent` → `Care_Center`, plus
  `Person_Title` and the **center's active academic year** (`Active_Academic_Year` → `Academic_Years`).
- Returns child/parent/spouse/class names, `invoice_title`, `invoice_date` (`dd/MM/yyyy`),
  `center_invoice_number`, and center name/logo/landline/address.
- The C# then adds `center_logo_stream` (the center logo bytes) and, only when `use_images`, the
  Invoice header/footer image bytes.

### 2b. What the slip actually prints (from the samples)

| Slip label | Value in sample (Mazen) | Modern source |
|---|---|---|
| Header banner | Summer Vacation image | `Center_Printable_Report_Settings` (type 1) `header_image` when `use_images` |
| Parent | Monir Itani | `vwChildClassParent.parent_name` |
| Spouse | *(empty)* | `vwChildClassParent.spouse_name` (`''` → `null`) |
| Student | Mazen | `vwChildClassParent.child_name` |
| Student ID | 22730 | `child_id` (verified: `registration_id` is NULL on all three samples) |
| Class | Birds | `vwChildClassParent.class_name` |
| Academic Year | 2019-2020 | **center's active year**, see §2c |
| Due Date | 15/06/2026 | `Fees_Installments.due_date`, `dd/MM/yyyy` |
| Issue Date | 27/08/2021 | `Child_Invoice.invoice_date`, `dd/MM/yyyy` |
| Amount | 2,532.00 **USD** | `installment_amount`, thousands separator + `Currency.currency_name` |
| Status | Pending / Paid / Cancelled | `is_paid`, then `installment_status = 0`, see §2c |
| Amount in words | Two thousand five hundred thirty-two USD only | computed in Nursery, see §2c |

There is **no page footer** (render date / title / page numbers) on any legacy slip. Decided: match
legacy and render none (§3).

**Not printed** even though the SP returns them: payment amount, payment date, payment note, receipt
number, payment type, invoice number, invoice title, and center name/address/landline. The Farah
sample (Paid) confirms that a paid installment shows only the status word. **The payload carries only
the printed fields** (skill 12 §7).

### 2c. Computed in NurseryServices-Web

New `GET` in the existing `payment/payment-tuition/export` module (§7). The steps:

1. **Ownership and RBAC.** Reuse the existing `getOwnedInvoiceData(centerId, userId, invoiceId)`
   unchanged. It checks invoice → center → `vwChildClassParent` → `canAccessClass`. Then load the
   installment with `fee_installment_id = :installmentId AND child_invoice_id = :invoiceId AND
   installment_status <> -1` (or NULL). A mismatch or deleted installment returns **404**, so an
   installment of another invoice can never be printed under this invoice's access check.
2. **Position.** Count and rank among the invoice's `installment_status <> -1` rows **ordered by
   `fee_installment_id`**, the legacy order. (The invoice schedule in §1b orders by due date. That is
   intentionally not copied here, because the slip must say the same "n / N" legacy printed.)
3. **Academic year: legacy behaviour.** Use the **center's active academic year**, as
   `getInvoiceInfo` does, **not** `Child_Invoice.academic_year`. That column is NULL on all three
   sample invoices, so the invoice export's approach would print an empty field where legacy prints
   `2019-2020`. Needs the `ActiveAcademicYear` entity (already exists) added to the module's
   `forFeature`.
4. **Dates.** `dd/MM/yyyy` for both due date and issue date, matching the samples. Note this
   **differs from the invoice export's `MM/dd/yyyy`** for its own issue date. Each report matches its
   own legacy sample (same rule the receipt doc applied). `due_date` is a SQL DATE hydrated as a
   `YYYY-MM-DD` string, so it is formatted from the string without a timezone shift (same care as the
   existing `formatInstallmentDate`, but day-first).
5. **Amount.** `toLocaleString('en-US', { minimumFractionDigits: 2, maximumFractionDigits: 2 })`
   → `"2,532.00"`, the same as the receipt export. Fractional last installments exist (Mazen's 10th is
   `2535.08`), so the cents must survive.
6. **Amount in words: sentence case.** The samples print `"Two thousand five hundred thirty-two USD
   only"`. The existing in-house helpers (invoice and receipt exports) produce **Title Case**
   (`"Two Thousand Five Hundred Thirty-Two USD only"`) despite the receipt doc's comment saying
   otherwise. This report matches its sample: sentence case, i.e. first word capitalised and the rest
   lower-case, with the currency code kept as-is. The fractional form (`"… and 8/100 USD only"`) is
   carried over from the existing helpers, not confirmed by a legacy sample. See §6.
7. **Status** (decided): `is_paid` → `'paid'`; otherwise `installment_status = 0` (cancelled /
   terminated) → `'cancelled'`; otherwise `'pending'`. This is a **deliberate change from legacy**,
   which would print a cancelled installment as "Pending". The precedence (paid wins) matches the
   existing invoice `installmentSchedule` mapping, so both documents agree. Cancelled installments stay
   printable and stay counted in "n / N", exactly as legacy counted them.
8. **Images** via `ReportImageLoaderService`, all nullable, never throwing:
   `loadPrintableReportImage(centerId, header_image)` / `(…, footer_image)` from the Invoice (type 1)
   settings row. No center logo is loaded, because the slip doesn't print one (see the bottom-image row
   in §2b). A `null` image renders blank. There is no default image (skill 12 §5).
9. POST the assembled `InstallmentReportTemplateData` with `meta: buildReportMeta(locale)` through
   `ReportingClientService.render('installment', …)`.
10. **Filename**: `"{studentName} {invoiceTitle} Installments.pdf"`, exactly legacy's
   `child_name + " " + CleansingString(invoice_title) + " Installments.pdf"`, sanitized for
   `\/:*?"<>|`. Built in the service and returned as `{ buffer, fileName }`.

## 3. Endpoint (this service)

```
POST /reports/installment
```
- `@UseGuards(InternalApiKeyGuard)`, internal-only like every other report.
- `@Body() templateData: unknown`, validated by `ReportPayloadValidator` against
  `installmentReportSchema` (same untyped-body pattern as the receipt controller).
- `@Header('Content-Type', 'application/pdf')`, raw PDF buffer.

`InstallmentReportsService.createPdfFromData` is the same shape as `ReceiptReportsService`:
validate, then `pipeline.render({ reportType: 'installment', templatePath:
'installment-report/installment-report.hbs', layout })`, with a **fixed** layout:

```ts
layout: (context) => ({
  format: 'A5',
  landscape: true,                       // the legacy slip is a landscape half sheet
  margin: { top: '15px', right: '15px', left: '15px' },
  footerTitle: context.labels.report.footerTitle ?? 'Installment',
  textFooter: false,                     // legacy slip has no date / page-number footer
  marginBottom: '15px',
}),
```

**Small shared-pipeline change (no-footer option).** Today every report gets the text footer:
`PdfRendererService` hard-codes `displayHeaderFooter: true`. Proposed:
- `ReportLayout.textFooter?: boolean`, default `true`, so every existing report is unchanged.
- When `false`, the pipeline passes `displayHeaderFooter: false` (no `footerTemplate`) and uses the
  layout's `marginBottom` as the bottom margin. `pageFillHeight` already takes that margin, so
  `.page-fill` still pushes the footer banner to the bottom of the page.
- Unit-tested in `report-render.integration.spec.ts`: one case with the footer off, plus the existing
  cases staying green.

Registration points (each a one-line addition):
- `report-schemas.ts`: `installmentReportSchema`, add `'installment'` to `ReportType` and
  `REPORT_SCHEMAS`.
- `app.module.ts`: `InstallmentReportsModule`.
- `i18n/{en,fr,ar}/reports.json`: an `installment` namespace (§5).
- `test-fixtures.ts` / validator spec: an installment fixture, the same as the other types get.

## 4. `InstallmentReportTemplateData` contract

```ts
export interface InstallmentReportTemplateData {
  settings: {
    useImages: boolean;                 // Center_Printable_Report_Settings.use_images, type 1 (Invoice)
    includeFooter: boolean;             // use_images && include_footer, same rule as the invoice export
    headerImageBase64: string | null;
    footerImageBase64: string | null;
  };
  installment: {
    parentName: string | null;
    spouseName: string | null;
    studentName: string;
    studentId: number;                  // Child.child_id
    className: string | null;
    academicYearTitle: string | null;   // center's ACTIVE academic year (legacy), not the invoice's
    dueDate: string;                    // "15/06/2026", dd/MM/yyyy
    issueDate: string;                  // "27/08/2021", dd/MM/yyyy (Child_Invoice.invoice_date)
    amount: string;                     // "2,532.00", pre-formatted
    currencyCode: string;               // "USD"
    amountInWords: string;              // "Two thousand five hundred thirty-two USD only"
    status: 'paid' | 'pending' | 'cancelled'; // labels are localized by this service, see §5
    number: number;                     // 1-based position among non-deleted installments, by id
    count: number;                      // number of non-deleted installments on the invoice
  };
}
```

Runtime spec (`installmentReportSchema`), using the existing shorthands and limits:

```ts
export const installmentReportSchema: ObjectSpec = obj({
  settings: obj(bannerSettings, { required: true }),
  installment: obj(
    {
      parentName: str({ nullable: true, maxLength: SHORT_TEXT }),
      spouseName: str({ nullable: true, maxLength: SHORT_TEXT }),
      studentName: str({ required: true, maxLength: SHORT_TEXT }),
      studentId: num({ required: true, integer: true, min: 0 }),
      className: str({ nullable: true, maxLength: SHORT_TEXT }),
      academicYearTitle: str({ nullable: true, maxLength: SHORT_TEXT }),
      dueDate: str({ required: true, maxLength: 64 }),
      issueDate: str({ required: true, maxLength: 64 }),
      amount: str({ required: true, maxLength: 64 }),
      currencyCode: str({ required: true, maxLength: 16 }),
      amountInWords: str({ required: true, maxLength: 1_000 }),
      status: str({ required: true, enum: ['paid', 'pending', 'cancelled'] }),
      number: num({ required: true, integer: true, min: 1 }),
      count: num({ required: true, integer: true, min: 1 }),
    },
    { required: true },
  ),
});
```

Notes:
- **No `center` block at all.** The slip prints no center name, address, phone or logo; the only
  center-specific visuals are the banners in `settings`. This is a deliberate departure from the
  shared `centerSpec`, not an oversight.
- **`status` is an enum, not a display string.** "Paid"/"Pending" are labels, and labels belong to
  this service's i18n (the localization service's rule: Nursery owns values, the renderer owns
  labels). It also keeps Arabic/French output correct without Nursery knowing the words.
- **One installment, not an array.** This is the slip only (§1a).

## 5. `.hbs` template design (`src/templates/installment-report/installment-report.hbs`)

Block order taken from the samples:

```hbs
<body class="compact">
<div class="page-fill">

  {{> report-banner}}
  <hr class="banner-rule" />

  <div class="slip-grid">                         {{! two columns, label + value pairs }}
    <div><strong>{{labels.report.parent}}</strong> {{installment.parentName}}</div>
    <div><strong>{{labels.report.spouse}}</strong> {{installment.spouseName}}</div>

    <div><strong>{{labels.report.student}}</strong> {{installment.studentName}}</div>
    <div><strong>{{labels.report.studentId}}</strong> {{installment.studentId}}</div>

    <div><strong>{{labels.report.class}}</strong> {{installment.className}}</div>
    <div><strong>{{labels.report.academicYear}}</strong> {{installment.academicYearTitle}}</div>

    <div><strong>{{labels.report.dueDate}}</strong> {{installment.dueDate}}</div>
    <div><strong>{{labels.report.issueDate}}</strong> {{installment.issueDate}}</div>

    <div><strong>{{labels.report.amount}}</strong>
         <span class="amount">{{installment.amount}}</span> <strong>{{installment.currencyCode}}</strong></div>
    <div><strong>{{labels.report.status}}</strong>
         {{#if (eq installment.status 'paid')}}{{labels.report.statusPaid}}
         {{else if (eq installment.status 'cancelled')}}{{labels.report.statusCancelled}}
         {{else}}{{labels.report.statusPending}}{{/if}}</div>
  </div>

  <p class="amount-words"><strong>{{installment.amountInWords}}</strong></p>

  <p class="position">{{installment.number}} / {{installment.count}}</p>

  <div class="page-fill-spacer"></div>

  {{> report-footer-banner}}           {{! the bottom image: same partial as the invoice report }}

</div>
</body>
```

- **One template, one fixed geometry**: A5 landscape, `compact` body class (the existing shared
  `body.compact .report-banner img` cap of 70px applies). There is no size toggle, because legacy's
  slip was always the small layout.
- **The header banner is shown on A5 here.** That is the opposite of the receipt, whose A5 variant
  drops the banners. The legacy slip has a `…Customized` variant and all three samples show the
  banner, so the receipt rule must not be copied.
- `.amount` keeps `direction: ltr` / `white-space: nowrap`, the same bidi protection as the
  invoice/receipt amount cells.
- Grid columns use logical (`start`/`end`) alignment so the `ar` locale mirrors correctly.
- **No text footer** (render date · title · page n of N), matching legacy (§3's `textFooter: false`).
  `footerTitle`/`documentTitle` labels are still defined; the latter is the HTML `<title>`.

## 6. Open items before implementation

Decided (2026-11-03):
- [x] **`installment_status = 0`** (7,615 rows on the replica): shown as **Cancelled** (§2c step 7),
      still printable and counted. A deliberate change from legacy.
- [x] **Text footer**: none, matching legacy (§3, needs the small `textFooter` pipeline option).
- [x] **Bottom image**: the Invoice footer banner, rendered exactly as the invoice report does. Note:
      Demo Center's Invoice `footer_image` is empty **on the staging replica**, while the legacy
      exports (made on the other system) show the image. A local render against staging will
      therefore show no bottom image. That is expected and not a bug.

Still open:
- [ ] **Academic year on the existing invoice export**: the legacy Invoice sample also prints the
      center's active year (`2019-2020`), while `PaymentTuitionExportService` reads
      `Child_Invoice.academic_year` (NULL on every invoice checked). Flagged for the invoice export's
      owner; this report uses the active year (§2c step 3).
- [ ] **Amount in words casing**: sentence case for this report (sample). The invoice and receipt
      exports emit Title Case, which does not match their own legacy samples either (the Invoice
      sample reads `"One thousand USD only"`). Flagged, not changed here.
- [ ] **Fractional amounts in words**: `"… and 8/100 USD only"` is inherited from the existing
      helpers, unconfirmed against legacy `Tafkitgenerator`. Mazen's 10th installment (`2535.08`) is
      a ready test case if a legacy export of it can be produced.
- [ ] **Spouse/Parent title**: legacy also selects `person_title` (`parent_title`). None of the
      samples visibly prints it, so it is omitted.

## 7. NurseryServices-Web side (for reference, implemented after approval)

In the existing `src/modules/payment/payment-tuition/export/` module (no new module): the slip is an
invoice-scoped document, and this module already owns the invoice ownership check, images and
formatting.

- Controller (`tuition/invoices/export`):
  `GET :invoiceId/installments/:installmentId/ticket`, guarded by `JwtAuthGuard` +
  `CenterAccessGuard`, `@ReportTicketThrottle()`, `ReportLocaleQueryDto` for `locale`. Issues a ticket
  against the **existing** `download/:ticket` route, so there is no second download endpoint.
- Service: `generateInstallmentPdf(centerId, userId, invoiceId, installmentId, locale)` per §2c.
- DTO: `dto/installment-report-template-data.interface.ts` mirroring §4.
- Module: add `ActiveAcademicYear` to `forFeature`.
- Unchanged: the invoice ticket, `includeInstallments`, and its `installmentSchedule` (§1b).
- Docs: the module's `doc/README.md` gets the new endpoint row.
